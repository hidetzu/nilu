# 9. Garbage collection

What nothing can reach any more is freed. A program does not need to do anything.

## 9.1. What owns memory

The following hold memory.

| What | When it comes to be |
|---|---|
| a string | a literal, `..`, `tostring`, a value the library returns |
| a table | `{}` |
| a function value (a closure) | when `function(…) … end` is evaluated |
| a cell for a captured variable | when a closure captures a variable outside it |
| a native function of the host's with values | when the host placed a function with values attached ([12. Embedding](12-embedding.md)) |
| `userdata` | when the host made one with `nilu_newuserdata` |
| a coroutine (a thread) and its stack | `coroutine.create`, `nilu_newthread` |
| an integer outside [-2^45, 2^45) | when such an integer is made; a smaller one is held in the value itself |

A float, an integer in [-2^45, 2^45), a boolean, `nil` and a native function of the host's with no values hold no memory of their own.

## 9.2. What is alive

What can be reached from the following is alive.

- the stack of the frames now running
- the main program's thread, and the thread now running; a suspended coroutine's stack is reached through the coroutine
- the table of global variables (`_ENV`)
- the bodies of the loaded functions
- what the host keeps in the registry (`nilu_ref`), and the reader and the writer it gave
- the values waiting to be closed (`<close>`), and the failure being carried

**What was put into a global variable is always alive.** Even when the host drops it from
the stack, it stays if it is in a global variable.

```lua nilu
local t = {}
t[1] = "値"
kept = t
t = nil
print(kept[1])
```
```output
値
```

### A weak table

**A table whose metatable has `__mode` does not keep what only it holds**.
With `"k"` in it, its keys are weak: an entry goes when its key is reached from nowhere else, and a
value that refers to its own key does not keep it. With `"v"`, its values are weak: a value reached
from nowhere else becomes `nil`, and its key stays. `"kv"` is both. A string, a number and a boolean
are never removed. This is Lua's `__mode`.

```lua nilu
local kept = {}
local cache = setmetatable({}, {__mode = "k"})
cache[kept] = "stays"
cache[{}] = "goes"
local names = setmetatable({}, {__mode = "v"})
names.a, names.b, names.c = kept, {}, "text"
collectgarbage()
local n = 0
for _ in pairs(cache) do n = n + 1 end
print(n, cache[kept], names.a == kept, names.b, names.c)
```
```output
1	stays	true	nil	text
```

A cycle is freed too. It is not reference counting but mark and sweep, so things that
only point at each other cannot be reached.

```lua nilu
for i = 1, 1000 do
  local a = {}
  local b = {}
  a[1] = b
  b[1] = a
end
print("循環を 1000 組作っても動き続ける")
```
```output
循環を 1000 組作っても動き続ける
```

**What this example proves is only that "it keeps running".** A program can see the effect of a
collection as a number, with `collectgarbage("count")` (the KiB the state holds) before and after
`collectgarbage()`; what confirms each freeing is this repository's Zig tests.

A variable a closure captured is alive as long as the closure is.

```lua nilu
local function hold()
  local secret = "持っている"
  return function() return secret end
end
local f = hold()
print(f())
```
```output
持っている
```

`hold` has long finished, and the register `secret` was in has long since been used for
something else. `f()` still answers because the captured variable moved into a cell and
the closure holds it ([6.4](06-functions.md#64-closures)).

## 9.3. When it happens

**A collection starts by itself only between one instruction of a Nilu function and the next.**
A program can also ask for one with `collectgarbage`, and a host with `nilu_gc`.

This means two things.

1. **If a C host keeps allocating without calling Nilu, that much keeps growing.**
   It never comes to a place where a collection starts by itself; `nilu_gc` collects.
2. **A loaded function is not freed.** A host that loads source repeatedly
   keeps growing until it closes the state, even when it loads the same text again.
   That is the price of there being one owner.
3. **A collection is started by how many objects there are, not by how large they are.**
   A program that makes a few large strings can hold far more than it keeps alive before
   a collection starts. Where that matters, the program calls `collectgarbage()`, or the
   host `nilu_gc`.

Seen from a program, a collection is invisible. The `nilu` command neither stops partway
nor comes back with a different state.

**`collectgarbage("stop")` keeps collections from starting by themselves** until
`collectgarbage("restart")`; `"isrunning"` says which. A collection asked for with `"collect"` or
`"step"` still runs. A program that must not pause for a while stops it, and restarts it after.

```lua nilu
print(collectgarbage("stop"), collectgarbage("isrunning"))
print(collectgarbage("restart"), collectgarbage("isrunning"))
```
```output
0	false
0	true
```

## 9.4. What there is not

| What there is not | What it means |
|---|---|
| finalisers (`__gc`) | there is no function called when something is freed |
| generational or incremental tuning | there is one method, a generational mark and sweep that decides by itself when to collect only what was made since the last collection and when to collect everything; `collectgarbage`'s `"incremental"`, `"generational"` and `"param"` are refused |

Since there are no finalisers, **an outside resource cannot be tied to a table and closed
automatically**. The host closes it itself.
