# 13. Lua との違い

Nilu は Lua 5.5 を一次資料として作られています。**互換を主張したことはありません。**
だから正しい言葉は「非互換」ではなく「違い」です。

違いは 4 種類あって、混ぜてはいけません。

| 種類 | 読み方 |
|---|---|
| **決めて変えたもの** | 理由があります。戻すときは理由を覆す必要があります |
| **仕組みが無いために違うもの** | 決めたのではありません。Lua の答えに要る仕組みが何かが書いてあります |
| **まだ無いもの** | 断ったわけではありません。何が要るかが書いてあります |
| **Lua が何も言っていないもの** | どちらでもよいところ。Nilu が決めたことを書きます |

## 13.1. 違うところ

### 決めて変えたもの

| 違い | Lua | Nilu | なぜ |
|---|---|---|---|
| **算術では文字列を変換しません** | `"1" + 1` は 2 | 型エラー | 変換は値の規則ではなく演算子の規則になります。`tonumber` を書きます。`..` と `table.concat` は数を `tostring` の綴りで受けます |
| **NaN はいつも `nan`** | `0 / 0` は `-nan` | いつも `nan` | 表示は Nilu 自身が書いています（C の `printf` に符号を渡していません）。**どの NaN も同じ綴りになります** |
| **`__call` の鎖は 1999 段まで** | 15 段まで | 1999 段まで（2000 段目で `'__call' chain too long`） | 上限の 2000 は `__index` の `MAXTAGLOOP` から借りていて、最後に呼ぶ関数も 1 段と数えます |
| **メタメソッドはメタテーブルの `__index` を通して継承されます** | どの名前もメタテーブル自身から読む（raw） | メタテーブルから読み、無ければメタテーブルのメタテーブルの `__index` にあるテーブルをたどる。2000 段まで。関数の `__index` は呼ばない（7.4） | ひとつの土台のメタテーブルに多くの名前をまとめて置けます。Python と PHP も特殊メソッドをクラスの鎖で同じように探し、`__getattr__` は走らせません。`__metatable` と `__gc` はメタテーブル自身のことを言う名前なので、今までどおりメタテーブル自身から読みます。届かない `__name` は失敗の文章では素の型名のままです |
| **`error()` が運ぶのは `nil`** | `pcall(error)` は `false <no error object>` | `false nil` | 失敗が運ぶのは値で、無ければ `nil` です |
| **ハンドラ自身の失敗では、ハンドラは 1 回だけ走ります** | ハンドラが失敗すると、上限まで何度も呼び直す | 1 回走って `error in error handling` | 入れ子を 1 段で止めています |
| **文字列でない失敗の値は種類で書きます** | `nilu -e 'error(1)'` は `1` | `runtime error` と `(error object is a number value)` | コマンドは文字列だけをそのまま書き、ほかの値は種類を言います。Lua の `msghandler` は数を文字列に変えます |
| **文字列でない失敗の値には呼び出し履歴が付きません** | 関数の中の `error({})` にも履歴が付く | 履歴なし | 履歴を付けるのは文字列の値のときだけです |
| **一番外で 1 段だけの失敗には呼び出し履歴が付きません** | `error("x")` でも `stack traceback:` と `[C]: in global 'error'` などが続く | `nilu: (command line):1: x` の 1 行だけ | 履歴は呼び出しが 2 段以上あるときだけ書きます。1 段の履歴は、すぐ上の行と同じ位置を繰り返すだけだからです（[11.3](11-nilu-command.md#113-失敗したときの書き方)） |
| **`for` から呼ばれた関数の断りは、その関数の名前を言います** | `for k in next, 1 do end` は `bad argument #1 to 'for iterator'` | `bad argument #1 to 'next'` | Nilu の `for` は呼ぶ側の名前を `for iterator` と名付けず、関数の登録名を使います |
| **ライブラリ関数の中でメモリが尽きると、ハンドラが走ります** | `xpcall` のハンドラは走らない | 走る（受け取るのは `not enough memory`） | ライブラリの確保は状態の外で行うので、その失敗は実行時エラーとして文章を運びます。VM の中で尽きたときは Lua と同じく走りません |
| **`<const>` に定数を入れても名前が付きます** | `local x <const> = 1; x()` は `attempt to call a number value` | `attempt to call a number value (local 'x')` | Lua は右辺が定数の `<const>` を使う場所へ埋め込み、変数を残しません。Nilu はどの `<const>` も読み取り専用のローカルとして残すので、失敗の文章に名前が付きます。そのぶんローカルの上限（200）にも数えられ、定数の `<const>` を 201 個並べると Lua は通し、Nilu は `too many local variables` と断ります |
| **数で引いたフィールドは `field '?'` です** | `t = {}` で `t[1].z` は `attempt to index a nil value (field 'integer index')` | `attempt to index a nil value (field '?')` | Lua が `integer index` と書くのは 0〜255 のリテラルキーだけで、これは `GETI` 命令が持てる範囲です。名前でないほかのキーは Lua でも `?` です。Nilu にその命令は無く、名前でないキーはすべて `?` と書きます（[8.1](08-failure.md#81-失敗したらどうなるか)） |
| **構文エラーに桁が付きます** | `f.lua:1: <name> expected near '='` | `f.lua:1:7: <name> expected near '='` | 文章は Lua から借りました。Lua は桁を持ちません。**文章が違うところもあります**：呼び出しでも代入でもない文（`x`、`f() = 1`、`a, b`）は文の先頭を指して `syntax error near 'x'` と言い、Lua はその後ろのトークンを指します（`a, b` では `'=' expected`）。閉じる語が足りず、開いた語が別の行にあるとき、Lua は `(to close 'if' at line 1)` を付けますが、Nilu は付けません |
| **構文の深さには上限があり、当たると上限を言います** | 上限は C のスタックで、括弧を 197 段重ねると `C stack overflow`（位置なし） | 入れ子や連なりが 200 段を超えると `chunk has too many syntax levels (limit is 200)`（位置付き）。チャンクの一番上なら括弧は 200 段まで読みます | 上限の 200 は Nilu が決めた数で、どこで止まったかを言います。どこまで深く書けるかは、まわりを何が囲んでいるかで変わります。長い式は途中を変数に置いて分けてください |
| **ソースは 4294967294 バイトまでです** | どんな長さでも読みます。行数が `int` を超えるチャンクは `chunk has too many lines` | それより長いソースは、読む前に 1:1 で `chunk is too large (limit is 4294967294 bytes)` と断ります | 構文木のノードを小さく保つため、オフセット・行・桁を 32 ビットで持ちます。行数の上限はバイト数の上限から決まります |
| **ライブラリの引数でも数を文字列に変えません** | `string.rep(1, 2)` は `11` | `bad argument #1 to 'rep' (string expected, got number)` | 自動変換が無いため、文字列を受ける引数に数を渡すと型を言って断ります。`os.getenv(1)` や `io.stdout:seek(1)` も同じです |
| **数でない文字列の算術は型の文章で断ります** | `"a" + 1` は `attempt to add a 'string' with a 'number'` | `attempt to perform arithmetic on a string value (constant 'a')` | Lua の文章は、文字列を数に変えようとする文字列のメタメソッドが出すものです。Nilu は変換しないので、型の文章になります |
| **`goto` の断りは `goto` を指します** | ブロックを読み終えたところ（`t.lua:4:`） | `goto` の行と桁（`t.lua:2:3:`） | エディタで飛んだ先が直す場所になるように。文言と `at line N` は Lua と同じです |
| **`__tostring` が数を返すと断ります** | 数を文字列にして使う（`true 1`） | `'__tostring' must return a string` | 自動変換が無いため。文章は Lua と同じです |
| **`pcall` はホストの中断を捕まえない** | 捕まえる | ホストまで巻き戻る | 止められないプログラムをホストが止められるように |
| **`==` が両方 `userdata` のとき `__eq` を呼びません** | 両方が full userdata なら呼ぶ（`getmetatable(io.stdout).__eq` を置いたあとの `io.stdout == io.stderr` が `true`） | 同じものかどうかだけ（`false`） | `__eq` を呼ぶのは両方がテーブルのときだけです。ほかのメタメソッドはテーブルと同じに答えます（[12.6](12-embedding.md#126-ホストのデータをプログラムに持たせる)） |
| **`math.tointeger` は文字列を変換しません** | `math.tointeger("8")` は `8` | `nil` | 算術と同じく、文字列から数を暗に作りません。`tonumber` を書きます |
| **浮動小数点数の表示は、読み戻せる最短の桁数です** | `print(1/3, 2^63)` は `0.33333333333333331	9.2233720368547758e+18`（15 桁で読み戻せなければ 17 桁） | `0.3333333333333333	9.223372036854776e+18` | 浮動小数点数の綴りは 1 つで、読み戻せば同じ値になる最短の桁数と決めてあります。`tostring` も `string.format` も同じ関数で綴ります。`%g` の形と、読み戻して同じ値になることは Lua と同じで、違うのは桁数だけです（[2. 値](02-values.md)） |
| **組み込みのライブラリに `io`・`os` がありません** | `io`、`os` は標準ライブラリ | `nilu_openlibs` は開かない。`nilu` コマンドが自分のものを持ちます | 中核は外のもの（ファイル、時計、プロセス）に触れません。それはホストのものです（[11.4](11-nilu-command.md#114-io-と-os)） |
| **`print` はホストが渡す writer を通して書きます** | `print` は C ライブラリの標準出力へ書く | `print` は `nilu_setwriter` で渡された writer に行を渡す。無ければ `cannot print: no writer was given to this state` で失敗します（[1.3](01-getting-started.md#13--print-はホストが決めた先へ書きます)） | 出力先はホストのもの（ゲーム、エディタ、サーバーでそれぞれ違う）で、`print` はどのホストでも同じに振る舞います |
| **`require` は求めたファイルの隣を探します** | `package.path` の型で、カレントディレクトリから | 読み込み中のファイルの隣、次に起動したスクリプトの隣。決めるのはホストの読み手（[11.6](11-nilu-command.md#116-require-が探す場所)） | どこから起動しても、プログラムのモジュールが見つかるように |
| **`package.loaded` はモジュールを見つかった場所で保ちます** | 書かれた名前で | 読み手の鍵（`lib/util.nilu`）で | 別々のディレクトリにある同じ名前の二つのモジュールが、二つのままでいるように |
| **`package` に探し方の設定はありません** | `package.path`・`cpath`・`searchers`・`searchpath`・`config`・`loadlib` | `package.loaded` と `package.preload` だけ | モジュールを探すのはホストの読み手なので、ゲームやエディタはアーカイブからも読めます。コマンドの読み手は求めたファイルの隣を探します（[11.6](11-nilu-command.md#116-require-が探す場所)） |
| **`collectgarbage` にモードはありません** | `"incremental"`・`"generational"`・`"param"` | 断ります（`invalid option`）。`"stop"` と `"restart"` はあります | 回収器は一つで、新しいものだけを回収するか全体を回収するかを自分で決める世代別の印付けと掃き出しなので、切り替えるものも調整するものもありません（[9.4](09-gc.md#94-無いもの)） |
| **`require` の循環は断ります** | `C stack overflow` まで繰り返しファイルを読む | `cannot load module 'a' while it is loading (a.nilu -> b.nilu -> a.nilu)` | 循環が閉じたところで、その循環を名指しします |
| **`load` と `loadfile` はテキストだけを受けます** | 断片を返す関数、バイナリのチャンク、テキストとしての数 | 文字列、`t` を許す mode。`load(1)` は `bad argument #1 to 'load' (string expected, got number)` | バイナリのチャンクは無く、数は文字列になりません |
| **`string.dump` はありません** | 関数のバイナリのチャンクを返し、`load` が mode `"b"` で読み戻す | `string.dump` は `nil` | バイトコードは内部の形で、どの版でも変わりえます。プログラムはソースのまま運びます（オーナーの答え） |
| **`debug` は `traceback` と `getinfo` だけです** | `getlocal`、`setlocal`、`setupvalue`、`upvaluejoin`、`sethook`、`getregistry` を含む 16 の関数 | `debug.traceback` と `debug.getinfo` | 関数を外から書き換えるものは入れません（オーナーの答え）。ホストには `nilu_sethook` があります |
| **`dofile` と `loadfile` にはパスが要ります** | 無ければ標準入力を読む | `bad argument #1 to 'dofile' (string expected, got no value)` | ライブラリは自分では何も読まず、パスにはホストの読み手が答えます |
| **C の API：多くの関数が状態を返し、C の中を飛びません** | `lua_pushnumber` や `lua_settop` は何も返さず、失敗すると飛ぶ。`lua_error` は戻らない。積む前に `lua_checkstack` で確かめる | 積む関数、表を読み書きする関数、呼ぶ関数は `NiluStatus` を返す。`nilu_compare` は状態を返して答えを積み、`nilu_next` は無いキーを状態で答え、`nilu_error` は戻ってきて `NILU_FAIL` を返す。`lua_checkstack` にあたるものはありません | 積むことは断られることがあり、Nilu は C の中を飛ぶ仕組みを持ち込まずに返り値で言います。どの積む呼び出しもその場で答えるので、前もって確かめる呼び出しは要りません（[12.3](12-embedding.md#123-ほとんどの関数は状態を返します)） |
| **C の API：型タグの番号は Nilu のもの** | `LUA_TNIL` は 0、`LUA_TBOOLEAN` は 1、… | `NILU_TNIL` は 0、`NILU_TNUMBER` は 1、… | Lua のタグには Nilu に無い型があるためです。`NILU_TNONE`（`-1`）の考え方は `LUA_TNONE` から借りています。番号ではなく名前で比べてください |
| **C の API：作るのと閉じるのは `nilu_new` と `nilu_close`** | `lua_newstate` と `lua_close` | `nilu_new` と `nilu_close` | 対になった名前のほうが読みやすいためです |
| **C の API：`userdata` は終了処理を持ちません** | `__gc` が回収のときに呼ばれる | `__gc` を持つメタテーブルを `userdata` に付けると `NILU_ERR_TYPE` | `userdata` が持つのは自分のバイトだけで、塊は回収のときにそのまま空きます。外の資源はホストが自分で閉じます |
| **テーブルの `__gc` は読みません** | 回収のときに `__gc` が呼ばれる | 何も呼ばれません。置いても断りません | 閉じるのは `userdata` と同じくプログラムかホストです（オーナーの答え） |
| **C の API：軽い `userdata` はありません** | `lua_pushlightuserdata` がある | full の `userdata` だけ | full だけにすると決めたためです |
| **C の API：`nilu_tonumberx` は文字列を数にしません** | `lua_pushstring(L, "10")` のあとの `lua_tonumberx` は `10` を返し、`isnum` は 1 | 同じ並びで `0` を返し、`isnum` は 0 | 自動変換が無いためです。文字列を数として読むには `nilu_stringtonumber` を使います（[`include/nilu.h`](../../include/nilu.h)） |

### 仕組みが無いために違うもの

**決めたのではなく、Lua の答えに要る仕組みを Nilu が持っていないために違うところです。** 4 列目は何が無いかを言います。

| 違い | Lua | Nilu | 何が無いか |
|---|---|---|---|
| **`math.exp` などの実数の関数は、最後のビットが Lua と違うことがあります** | `math.exp(1)` は `2.7182818284590451` | `2.7182818284590455`（最後の桁 1 つぶん） | C ライブラリの数学関数。中核は libc ではなく Zig のものを使います |
| **呼ぶ側のコードが無いときの名前** | `pcall(string.rep)` は `'string.rep'` | `'rep'` | 呼ぶ側のバイトコードが無いと、登録された名前を使います。Lua は読み込まれたモジュールを探して `string.rep` と答えますが（`pushglobalfuncname`）、Nilu にはその表がありません。呼ぶ側も名前も無いと Lua は `'?'` と言い（`pcall(io.stdout.seek, io.stdout, "nope")` は `bad argument #2 to '?'`）、Nilu は登録された `'seek'` を言います。`local f = string.rep; f()` のように呼ぶ側がいれば、どちらも `'f'` です |
| **`__call` で呼ばれた関数の断りは、足された引数も数えます** | 足された引数は `bad extra argument #1 to 'c'`、書いた引数は `c({})` で `#1` | 足された引数は `bad argument #1 to 'c'`、書いた引数は `c({})` で `#2` | Lua は `__call` が前に足した引数を数えずに番号を言い、足された引数への断りには `extra` を付けます（`ar.extraargs`）。Nilu は足されたことを数えていないので、書いた引数の番号が 1 つ大きくなります。メソッドとして呼んだとき、Lua は受け手への断りを `calling 'm' on bad self` と言い、Nilu は `bad argument #2 to 'm'` と言います |
| **呼び出し履歴はメインチャンクで終わります** | 最後に `[C]: in ?` の行 | 最後の行は `in main chunk` | コマンド自身がチャンクを呼ぶ呼び出しはフレームではありません（[11.3](11-nilu-command.md#113-失敗したときの書き方)） |
| **`print` はグローバルの `tostring` を呼びます** | `tostring = function() return "X" end; print(1)` は `1` | `X` | 値を綴る C の呼び出し（`luaL_tolstring`）が境界に無いので、C の API で書かれたライブラリの `print` はプログラムの `tostring` を呼びます |
| **文字列の比較はバイトの大小** | C のロケール（`strcoll`）で比べる | バイトの大小で比べる | 中核が libc を使わないため。C ロケールでは一致します |
| **`upper`/`lower` は ASCII だけ** | ロケール依存 | ASCII | 中核が libc を使わないため。ASCII の範囲では一致します |
| **パターンの文字クラスは ASCII** | ロケール依存（`isalpha` など） | ASCII | 中核が libc を使わないため。`upper`/`lower` と同じ理由で、C ロケールでは一致します（[10.2](10-library.md#102-string)） |
| **`os.date` はいつも C ロケール** | `os.setlocale("ja_JP.UTF-8")` のあとは `%A` が `木曜日` | いつも英語（`os.date("!%A", 0)` は `Thursday`）。`os.setlocale` は `"C"` を返し、何も変えません（Lua では環境のロケールに切り替える `""` も） | `setlocale` を呼ばないので、`%c`・`%x`・`%A` などは C ロケールの答えです。Lua の既定も C ロケールなので、ロケールを変えなければ一致します |
| **`math.random` の初期状態は決まっている** | 開くたびに時刻とアドレスから種を取る | `math.randomseed(0)` と同じ列。`nilu` コマンドは起動時に種を与える | 中核は時計を持たないため。ホストが種を与えれば Lua と同じ振る舞いになります（[10.4](10-library.md#104-math)） |
| **`math.randomseed()` は生成器から種を取り直す** | 時計から | 生成器の次の値から | 中核は時計を持たないため。起動時に種があれば予測できないまま、無ければ決まった列のまま |
| **`table.sort` のピボットは固定** | 大きい配列では時計とアドレスで散らす | いつも中央 | 中核は時計を持ちません。結果は同じです |
| **呼び出しが深すぎるときの文章は 1 つ** | ライブラリ関数を挟むと `C stack overflow`（位置なし） | いつも `stack overflow`。上限に当たったのが Lua の関数なら位置が付き、ライブラリ関数なら付きません | Lua は Lua のスタックと C のスタックに別々の上限を持ちますが、Nilu は呼び出しの深さを 1 つの上限で数えます。`__tostring` や `sort` の比較関数が自分を呼び続けても、同じ文章で断られます |
| **C の API：`nilu_getupvalue`/`nilu_setupvalue` は走っているクロージャを指す** | `lua_getupvalue(L, funcindex, n)` はスタック上の関数を指し、C 関数は `lua_upvalueindex(n)` で自分の値を読む | `nilu_getupvalue(N, n)` と `nilu_setupvalue(N, n)` は、いま走っている C クロージャの値を番号で指す | 擬似インデックス（`lua_upvalueindex`）が無いためです。添字が値に届く道はスタックだけです（[12.8](12-embedding.md#128-無いもの)） |
| **定数は 1 つの関数に 65535 個まで** | 7 万個の異なる文字列を並べた表も読める | `too many constants (limit is 65535)` | 定数を指す番号の幅が 16 ビットだからです |
| **上限に当たると、超えた 1 個目を指します。汎用 `for` は 1 枠少なく数えます** | `too many local variables (limit is 200) in main function near 'do'`。位置はそのとき読んでいたトークンで、名前 1 個の汎用 `for` は 200 個のローカルのうち 4 個を使う | `too many local variables (limit is 200)` を、上限を超えた最初のものの位置で言う。201 個目の名前、256 個目の upvalue になる参照、65536 個目の定数になるリテラル、256 個目のレジスタが要る値。汎用 `for` は名前の数 + 2 個を使う | Lua の位置は、読み進んでいたところです。Lua は汎用 `for` の隠れた値を 3 つ 200 に数えますが、Nilu は 2 つです。ループが閉じる値は、ローカルとして数えないレジスタに置くので、汎用 `for` は閉じるためのローカルの枠を持ちません |

## 13.2. まだ無いもの

**「できません」ではなく「まだ実装していません」です。** 何が要るかを書きます。

### 言語

**Lua 5.5 の言語で無いものは、いまはありません**。最後に残っていたのは `<close>` と `...rest` でした。
次の 2 つは無いように見えますが、そうではありません。

⚠ **`...[1]` は無いものではありません。** **測定すると `lua5.5` 5.5.0 も Nilu も同じ文章で断ります**
（`'end' expected near '['`）。後ろに添字を続けられるのは名前と `( exp )` だけだからです。**どちらも断るので、違いではありません。**

⚠ **ASCII 以外の名前も無いものではありません。** これは無いものではなく **Lua の既定と同じ**だからです。
**測定すると `lua5.5` 5.5.1 も `local あ = 1` を断ります**（`<name> expected near '<\227>'`）。
Lua は `LUA_UCID` を定義してビルドしたときだけ受け付けます。

### ライブラリ

**Lua 5.5 のライブラリで無いものは、いまはありません。** 入れていないものは決めたことで、
[13.1](#131-違うところ) にあります。

### C の API

一覧は [12.8. 無いもの](12-embedding.md#128-無いもの) にあります。
**2 箇所に置くと片方が古くなるので、持っているのはあちらだけです**。
Lua 側の綴りを並べた列があります。

## 13.3. 代わりに何を書くか

上の表の「何が要るか」は、**その穴を埋めるのに何が必要か**です。
ここは別の問いに答えます —— **今日は何を書けばいいか**。
**下の例はすべて走らせて確かめたものです**（`zig build manual-check`）。

**Lua の文（`do … end`、`elseif`、`;`、`repeat … until`、`goto`、`t:m()`、`{1, 2}`、`f "x"`）はそのまま
書けます**。

### 関数とメソッド

**文字列のメソッドも、Lua と同じく `:` で呼べます。** `s:upper()` は `string.upper(s)` です。
すべての文字列が 1 つのメタテーブルを共有していて、その `__index` が `string` です（`getmetatable("")` で見えます）。

```lua nilu
local s = "Hello"
print(s:upper(), s:sub(1, 3), s:len(), getmetatable("").__index == string)
```
```output
HELLO	Hel	5	true
```

### 名前

ASCII 以外の名前は**使えません**（Lua の既定と同じです）が、**文字列の中身はどんなバイトでも
かまいません**。変数名だけ ASCII にしてください。

### そのほか

- **`xpcall`** はあります。ハンドラは Lua と同じく**巻き戻す前**に呼ばれます（[8.4.1](08-failure.md#841-xpcall)）。

### 代わりに書けないもの

**次のものは、ここに書き換えがありません。** 黙っているほうが不親切なので挙げます。

| 無いもの | なぜ書き換えられないか |
|---|---|
| テーブルの `__gc` | 解放のときに呼ばれるものはありません。持っているものはプログラムが閉じるか、`<close>` を使います |

## 13.4. Lua から借りて、同じにしているもの

移植するときに**気にしなくてよい**ところです。

- 真偽の規則（`false` と `nil` だけが偽）
- 演算子の優先順位と結合、`^` と `..` が右結合
- `%` が負の無限のほうへ切り捨て、`math.fmod` は 0 のほうへ
- `/` がいつも実数の除算、`//` が切り捨て除算
- 添字が 1 から、負の添字は後ろから
- `#` の境界（穴があれば決まっていません）
- `pairs` の順序が決まっていないこと
- 複数の値の規則（ならびの最後だけが広がる、`(f())` は 1 つ）
- 末尾呼び出しがフレームを作り直すこと
- `for` の制御変数が読み取り専用であること（5.5 の変更）
- `__index` の鎖、`>` が `<` を使うこと（`__eq` が `userdata` 同士で呼ばれないのは 13.1 の違いです）
- `__metatable` によるメタテーブルの保護
- 数の表示が `%g` の形で、読み戻せば同じ値になること（桁数は [13.1](#131-違うところ)）
- `tonumber` が前後の空白を許し、余った文字を許さないこと
- `inf`/`nan` という綴りを数として読まないこと
- グローバル変数が `_ENV` のフィールドであること

## 13.5. Lua が何も言っていないところ

- **`tostring` のテーブルと関数の表し方**。形は Lua から借りた `type: identity` ですが、
  中身は約束されていません。実行ごとに変わります
- **`pairs` の実際の順序**。Lua も約束していません。Nilu は連番として持つキー 1, 2, 3, … を
  順に歩き、残りはハッシュの並び順で、こちらはテーブルが育つと変わります
- **`#` が穴のあるテーブルで返す値**。どの境界かは決まっていません
- **1 つのコンストラクタで同じキーに 2 回書いたとき、どちらが残るか**。
  `{x = 1, x = 2}` は後の勝ちですが（Lua も同じ）、**キーを書いた要素とキーを書かない要素が
  ぶつかる `{"あ", [1] = "い"}` は決まっていません。** Lua 自身の答えが**空きレジスタの数で
  変わります** —— 測定したところ、ローカル変数 199 個の関数の中では `い`、0 個の関数の中では
  `あ` でした（`lua5.5` 5.5.0）。Nilu は仕組みごと借りているので同じ隅を引き継ぎます
