# 9. ガベージコレクション

どこからも届かなくなったものは解放されます。プログラムが何かする必要はありません。

## 9.1. 何が所有しているか

メモリを持っているのは次のものです。

| もの | いつできるか |
|---|---|
| 文字列 | リテラル、`..`、`tostring`、ライブラリの返り値 |
| テーブル | `{}` |
| 関数値（クロージャ） | `function(…) … end` を評価したとき |
| 捕まえた変数の入れ物 | クロージャが外の変数を捕まえたとき |
| 値を持ったホストの C 関数 | ホストが値を添えて関数を置いたとき（[12. 組み込み](12-embedding.md)） |
| `userdata` | ホストが `nilu_newuserdata` で作ったとき |
| コルーチン（スレッド）とそのスタック | `coroutine.create`、`nilu_newthread` |
| [-2^45, 2^45) の外の整数 | そういう整数ができたとき。それより小さい整数は値そのものに収まります |

浮動小数点数、[-2^45, 2^45) の整数、真偽値、`nil`、値を持たないホストの C 関数は、それ自体がメモリを持ちません。

## 9.2. 何が生きているか

次のものから辿れるものが生きています。

- いま走っているフレームのスタック
- メインのプログラムのスレッドと、いま走っているスレッド。止まっているコルーチンのスタックは、そのコルーチンから辿ります
- グローバル変数のテーブル（`_ENV`）
- 読み込まれた関数の本体
- ホストがレジストリ（`nilu_ref`）に置いたもの、ホストが渡した読み手と書き手
- 閉じるのを待っている値（`<close>`）と、運ばれている失敗

**グローバル変数に入れたものは、必ず生きています。** ホストがスタックから
落としても、グローバル変数にあるなら残ります。

```lua nilu
local t = {}
t[1] = "値"
kept = t
t = nil
print(kept[1])
```
```output
値
```

### 弱いテーブル

**メタテーブルに `__mode` があるテーブルは、自分だけが持っているものを生かしません**。
`"k"` を含むとキーが弱く、キーがほかから届かなくなるとその項目が消えます。自分のキーを指す値は、そのキーを生かしません。
`"v"` を含むと値が弱く、ほかから届かない値は `nil` になり、キーは残ります。`"kv"` は両方です。
文字列、数、真偽値は消えません。Lua の `__mode` と同じです。

```lua nilu
local kept = {}
local cache = setmetatable({}, {__mode = "k"})
cache[kept] = "stays"
cache[{}] = "goes"
local names = setmetatable({}, {__mode = "v"})
names.a, names.b, names.c = kept, {}, "text"
collectgarbage()
local n = 0
for _ in pairs(cache) do n = n + 1 end
print(n, cache[kept], names.a == kept, names.b, names.c)
```
```output
1	stays	true	nil	text
```

循環していても解放されます。参照カウントではなく、印を付けて掃く方式なので、
互いを指し合っているだけのものは届きません。

```lua nilu
for i = 1, 1000 do
  local a = {}
  local b = {}
  a[1] = b
  b[1] = a
end
print("循環を 1000 組作っても動き続ける")
```
```output
循環を 1000 組作っても動き続ける
```

**この例が証明しているのは「動き続けること」だけです。** 回収の効き目は、`collectgarbage()` の前後で
`collectgarbage("count")`（状態が持っている KiB）を比べれば数として見えます。一つ一つの解放を
確かめているのは、このリポジトリの Zig のテストです。

クロージャが捕まえた変数も、クロージャが生きているあいだ生きています。

```lua nilu
local function hold()
  local secret = "持っている"
  return function() return secret end
end
local f = hold()
print(f())
```
```output
持っている
```

`hold` はもう終わっていて、`secret` が入っていたレジスタはとうに別の用途に
使われています。それでも `f()` が答えるのは、捕まえられた変数が入れ物に移って
クロージャがそれを持っているからです（[6.4](06-functions.md#64-クロージャ)）。

## 9.3. いつ起きるか

**回収がひとりでに始まるのは、Nilu の関数の命令と命令の間だけです。**
プログラムは `collectgarbage` で、ホストは `nilu_gc` で回収を求めることもできます。

これが意味することが 2 つあります。

1. **C のホストが Nilu を呼ばずに確保を続けると、そのぶんは増え続けます。**
   回収がひとりでに始まる場所に来ないからです。`nilu_gc` なら回収します。
2. **読み込んだ関数は解放されません。** ソースを繰り返し読み込むホストは、
   状態を閉じるまで増え続けます。所有者がひとつであることの代金です。

プログラムから見ると、回収は見えません。`nilu` コマンドが途中で止まることも、
別の状態が返ることもありません。

**`collectgarbage("stop")` は、回収がひとりでに始まらないようにします**。`collectgarbage("restart")` まで続き、
どちらなのかは `"isrunning"` が答えます。`"collect"` や `"step"` で頼んだ回収は止まっていても走ります。
しばらく止まってほしくないプログラムは、止めておいて、あとで再開します。

```lua nilu
print(collectgarbage("stop"), collectgarbage("isrunning"))
print(collectgarbage("restart"), collectgarbage("isrunning"))
```
```output
0	false
0	true
```

## 9.4. 無いもの

| 無いもの | 意味 |
|---|---|
| ファイナライザ（`__gc`） | 解放のときに呼ばれる関数はありません |
| 世代別・増分の調整 | 方式は世代別の印付けと掃き出しひとつで、前回の回収のあとに作られたものだけを回収するか、全部を回収するかは回収器が自分で決めます。`collectgarbage` の `"incremental"`・`"generational"`・`"param"` は断ります |

ファイナライザが無いので、**外の資源をテーブルに結びつけて自動で閉じることは
できません**。ホストが自分で閉じてください。
